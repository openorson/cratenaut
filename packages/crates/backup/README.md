# Backup Crate

`backup` 暂不实现，本目录用于保留已经确认的问题、边界和后续设计方向

## 为什么暂缓实现

备份不能只理解为压缩持久化目录。不同数据源需要不同的一致性策略：

- 数据库运行时直接复制数据目录可能得到无法恢复的备份
- 不同 `crate` 的数据可能分布在多个存储卷中，需要确定一致性边界
- 备份成功不等于能够恢复，还需要校验归档、清单和恢复流程
- 定时执行、保留策略、并发控制和失败重试需要统一的运行机制
- 本地目录和兼容 `S3` 的对象存储需要一致的目标抽象
- 凭据、归档加密密钥和恢复密钥都属于敏感数据，不能出现在命令参数或日志中
- 访问容器、数据库和宿主机目录会扩大权限范围，需要明确最小权限模型

在这些问题没有形成稳定契约前，不提供一个看似通用但不可靠的实现

## 建议的备份流程

后续实现应当采用可组合的流水线：

1. 发现声明为可备份的存储及其数据源
2. 由数据源适配器创建一致性快照或逻辑导出
3. 生成归档、校验和与备份清单
4. 将产物写入本地目录或兼容 `S3` 的对象存储
5. 应用保留策略并清理过期备份
6. 定期执行恢复校验，确认备份实际可用

兼容 `S3` 的对象存储可优先使用 `Bun` 的 `S3Client`，同时保留本地目录目标，便于离线环境和用户自行接管备份产物

## 待确定的契约

- 通用冷备份与各 `crate` 专用适配器之间的职责边界
- 数据库逻辑备份、文件快照和停机备份的统一描述方式
- 手动、系统定时器和常驻调度服务之间的执行方式
- 本地目录与兼容 `S3` 对象存储的目标抽象
- 全量备份、增量备份、保留数量和保留周期的策略模型
- 归档压缩、客户端加密、校验和与密钥轮换方式
- 恢复到原实例、恢复到新实例和仅下载产物的命令体验
- 备份清单格式、版本兼容规则和恢复演练机制

## 当前边界

- 不导出任何可用的 `backup crate`
- 不承诺当前目录中的接口或选项
- 其他官方 `crate` 只需为持久化资源提供稳定标识及备份元数据，不依赖本包
